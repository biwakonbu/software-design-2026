# 第7回: 架空の提出例を講評する

全て教材用に作成した架空例です。実在の提出者・提出コード・評価は含みません。Python 3.12以上で、ルートから実行します。

```sh
python3 examples/07-review/flawed_route.py A D
python3 examples/07-review/improved_route.py A D
```

| ファイル | 役割 |
| --- | --- |
| `review_data.py` | 講評用グラフとCLI。第6回とは別の架空グラフ |
| `flawed_route.py` | 誤りを含む公開例。DFSの最初の経路を最短と誤解 |
| `improved_route.py` | BFSで辺数最小を求める公開改善例 |

グラフはA–B–E–F–DとA–C–D、孤立点Xです。DFSの経路`A -> B -> E -> F -> D`は各辺が存在し、終点にも着きますが4辺。BFSの`A -> C -> D`は2辺です。「到達できる」テストだけでは最短性の誤りを見落とします。

誤例は閉路で止まらなくなる例ではなく、訪問済み管理付きのDFSです。誤りはDFSそのものではなく、この探索が返す最初の経路に「最短」の保証を付けた点です。CLIは誤例であることを表示します。

改善例の関数は`find_route(graph, start, goal) -> list[str] | None`。入力は無向・重みなし隣接リスト、未知駅/不整合は`ValueError`、到達不能は`None`、同駅は`[start]`。CLIは`START GOAL`（既定A D）で、成功時0、入力エラー・経路なしで2。第6回と同じ形式で、経路と移動数を出力します。

講評では、まず仕様と期待値を確認し、失敗を再現する小さな入力を示してから、原因と修正理由を説明します。人への評価とコードの性質を混ぜず、例えば「この入力で4辺を返すが2辺の経路がある。幅優先順なら辺数順に候補を検査できる」と具体的に述べます。

質疑では次を自分の実装で説明してください。

- BFSの最短性は何を最小化するか。重みが違ったらどうなるか。
- 経路が有効である確認と、経路が最短である確認はどう違うか。
- キューと訪問記録はいつ変わるか。閉路でもなぜ終了するか。
- 同駅、到達不能、未知IDに別の意味を持たせる理由は何か。
- AIを用いた場合、どの提案を採用し、どの反例・検証で確認したか。

`python3 -m unittest discover -s tests -p test_foundations.py`は4辺対2辺の反例、経路の有効性、境界、CLIを確認します。さらに4頂点の全無向グラフと全始終点について、改善例を単純経路の全探索と照合します。これは公開サンプルの検証であり、実在の学生提出の採点ではありません。
