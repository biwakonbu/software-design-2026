# 第3回　AI時代の学習と開発

## 到達目標

生成AIを学習と開発に使い、採用の判断を反例・実行結果・説明で支える。Python 3.12以上、エディタ、第2回の集計コードを用意する。サービス固有の有料契約は教材の必須条件ではない。

## A　学習の依頼

説明しづらいPythonの概念を1つ選ぶ。自分の予測・疑問を書き、AIに小さな例や質問を依頼する。回答と異なる入力を自分で作り、手元で実行する。自分の説明がどのように変わったか200字程度で残す。

## B　二分探索の診断

examples/03-ai-workflow/binary_search_buggy.pyは検証教材として自作した誤りの例。整列済み整数リストから一致する添字を返し、不在ならNoneという仕様。重複は任意の一致を認める。未整列入力は対象外。

1. `[1]` から1を探す場合を追跡し、失敗を再現する。
2. バグの原因候補と、候補を区別するテストをAIに尋ねる。
3. 修正を `submission/03/search.py` に作る。完成例をコピーする前に、探索範囲が閉区間か半開区間かを決める。
4. 空・1要素・末尾・不在・重複の5種類をテストする。重複例の期待値は「返した添字の値がtargetと一致する」でもよい。
5. `verify.py` と修正版を参照し、自分の判断を比較する。

```bash
python3 examples/03-ai-workflow/verify.py
python3 -m unittest discover -s submission/03 -v
```

## C　相互説明

相手が選んだ入力に対する結果を、実行前に予測する。境界の更新と終了条件を説明し、実行後に一致を確認する。本人のコードの仕様を質問する活動であり、他人の提出物をAIへ送る必要はない。

## 提出物

search.py、test_search.py、README.md、reflection.md。記録には依頼の要点、採用/却下した候補と理由、期待値の求め方、実行結果、残っている前提を含める。提出先・期限は授業の案内に従う。

AIを使える環境がない場合は、スライドの提案例をAIの候補と見立て、相互質問で同じ検証手順を行う。環境状況と実際に行った手順を記録する。個人情報・秘密情報を依頼に含めない。

## 確認問題

説明の流暢さと正しさの違い、1要素の反例の意味、AIが作る期待値の検証、却下した提案の記録を、それぞれ自分の作業に結び付けて説明する。
