# 第04回 演習：処理順と増え方

学生用。Python 3.12以上の環境で、リポジトリのルートから実行する。`python3 --version` で利用中の版を確認する。正式な提出先・期限は授業時の案内に従う。以下は本教材の推奨成果物。

## 準備

`work/04` を作り、記録用の `04-observations.md` を置く。

```bash
mkdir -p work/04
python3 examples/04-algorithms/containers.py
python3 examples/04-algorithms/trees.py
```

まず実行せずに、A、B、Cをこの順に追加したときのスタックとキューの取り出し順を予測する。木はAの子がB、C、Bの子がD、E、Cの子がF。子の列挙順を保ってDFSとBFSの訪問順を予測する。

検証の基準は、スタックがC B A、キューがA B C、木のDFSがA B D E C F、BFSがA B C D E Fとなること。実演出力と照合し、異なる場合は取り出し方法と子の順を調べる。

## 段階1：探索を実装する

`work/04/04-search.py` に、線形探索と二分探索を作る。どちらも一致する要素のインデックスを1つ返し、不在なら `None` を返す。二分探索の入力は昇順に整列済みであること。重複の先頭を返すことは、この段階の要件に含めない。

入力 `[8, 2, 6, 4]` と値6を使う。線形探索の期待値は2。二分探索には整列したコピー `[2, 4, 6, 8]` を渡し、期待値は2。このインデックスは整列後の列に対応する。元の列の位置に戻したい場合は、追加の設計が必要になる。

次の条件も自分で追加する。

- 空列で不在を返す
- 先頭と末尾の要素を見つける
- 存在しない値を調べる
- 1要素の列で一致・不一致を調べる

```bash
python3 work/04/04-search.py
python3 examples/04-algorithms/sorting_search.py
```

参考デモのソート入力は `[7, 2, 4, 2, 9]`、整列後は `[2, 2, 4, 7, 9]`。自分の入力の結果と混同しない。

## 段階2：候補数を数える

3要素の列で、異なる2要素を選ぶ候補をすべて列挙する。`i < j` として、同じ組の重複を避ける。候補数は3。4要素なら6、5要素なら10になることを確認する。

「全探索」という名前だけで計算量を決めず、候補の数と、候補1件の確認コストを説明する。巨大な列を作らず、小さい入力で増え方を確かめる。

## 段階3：メモリと操作数を読む

```bash
python3 examples/04-algorithms/memory_complexity.py
```

出力から入力サイズと操作数モデルの値を記録する。これは実際の処理時間・比較回数を測定した値ではなく、増え方を比較する計算モデルである。入力を2倍にしたとき、線形の操作数はおよそ2倍、二重ループの操作数は4倍という関係を説明する。デモが用いるサイズ・操作の定義をコードで確認する。

メモリのbyte数には、Pythonの版・処理系・環境による差がある。`sys.getsizeof` が直接測るオブジェクトと、その参照先を区別する。全データのbyte数と断定しない。
