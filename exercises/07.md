# 第07回 演習：講評と質疑

学生用。共通のレビューには本教材が自作した架空提出例を使う。実学生の提出物・評価・個人情報は含めない。自分の第06回の成果物を用意する。正式な再提出の扱いは授業時の案内に従う。

## 段階1：架空提出例を実行する

この回のグラフは第06回のデータと異なる。無向・重みなしの辺はA-B、B-E、E-F、F-D、A-C、C-D。孤立頂点Xを含む。

```bash
mkdir -p work/07
python3 examples/07-review/flawed_route.py A D
python3 examples/07-review/improved_route.py A D
```

架空提出例は訪問済みを管理したDFS。最初に得た経路A B E F Dを「最短」と表示する。移動数4。改善版はBFSでA C Dを返し、移動数2。この違いを図と出力で照合する。

`work/07/07-review.md` に、満たしている仕様、満たしていない仕様、反例、改善後に確認する条件を書く。経路が実在する点まで誤りと決め付けない。

## 段階2：テストを追加する

同駅A A、孤立駅A X、未知駅UNKNOWN Dを両方のCLIで試す。成功時の経路・辺数と、失敗時のメッセージ・終了コードを記録する。XからXは同駅なので経路X、移動数0となることも確認する。

発展として、作業コピーのグラフからA-Cの辺を両方向に削り、最少経路がA B E F D、4辺になるか検証する。その結果でも、元のDFSが一般に最短を保証するとは言えない理由を書く。共有の参考ファイルは変更しない。

## 段階3：改善の根拠を書く

「dequeを使ったから」だけで終えず、FIFOで近い層が先に処理され、未発見の頂点の親を最初の発見時に記録することを説明する。重みが異なるグラフなら、最少辺数と最少時間が一致するとは限らない。

講評文には、対象の入力、実際の結果、期待する振る舞い、改善後の確認方法を含める。能力や人格への評価を避け、コードの振る舞いを扱う。

## 段階4：自分の提出物を説明する

第06回のコードを開き、次の問いへ、該当箇所と具体的な入力を使って答える。

1. この関数が返す「最短」は、何を最少にした経路か。
2. キューと親辞書は、A Dの探索中にどう変化するか。
3. 同じ頂点がキューへ何度も入らない根拠はどこか。
4. 到達不能と未知の駅名をどう区別したか。
5. 自作テストは、どの実装ミスを検出する狙いで選んだか。
6. AIの提案を採用した箇所について、自分が確認したことは何か。

担当教員との授業内の質疑で説明する。説明に詰まった場合は、入力を小さくして状態を書き出す。質疑で気付いた疑問・修正点を残す。

## 段階5：改善を検証して記録する

`work/07/07-improvements.md` に、第06回の修正前後の振る舞い、再現入力、期待値、実際の結果を書く。修正が不要なら、確認した条件とその証拠を記す。AIを使用したか、何に使い、何を自分で検証したかを振り返る。

成果物の推奨構成は `07-review.md` と `07-improvements.md`。実装も修正した場合は、修正版コードとテスト結果を一緒に整理する。提出・再提出するかは授業時の案内に従う。
