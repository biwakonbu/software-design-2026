# 第8回　電卓の解析と実行

## 到達目標

字句・構文・意味の境界を、トークン、AST、テストで説明する。Python 3.12以上を使い、木の走査と関数を復習します。公開referenceはexamples/08-calculator/calculator.py、動作する拡張用starterはstarter.pyです。Pythonのeval/execは使いません。

## 当日の中心と進め方

まずAのトークン、Bの木と評価を通して、`2+3*4` の入力位置・規則の呼出し・部分ASTをつなぎます。Cでは、「完成基礎電卓を利用して拡張する」「自作で全実装する」のどちらの経路で進めるかを決めます。全処理系を白紙から書く作業と、解析の途中状態を説明する学習は、必要な作業量が異なります。以下の受入例と提出物は、どちらの経路でも共通です。

コマンドはリポジトリのルートから実行します。完成基礎電卓は動く状態を観察する入口であり、実行しただけでは本人の拡張実装を示したことにはなりません。

```bash
python3 examples/08-calculator/starter.py
python3 examples/08-calculator/calculator.py --eval '2+3*4'
```

starterはASTの表現と結果14.0を表示し、calculatorのCLIは14を表示します。どちらも同じ数値を計算しています。自分の変更・テストへ進む前に、小さい入力が動くことを確認します。

## A　トークンの追跡

`12+3.5*(2-1)` を種類・文字列・開始位置に分け、末尾eofも記録します。空白を挿入した場合、意味は同じで開始位置が変わることを確かめます。`2@3` を受理せず、@の位置を説明します。

## B　ASTと評価

`2+3*4`、`(2+3)*4`、`10-3-2` の木を描きます。期待値は14、20、5です。子の評価が終わるごとに、途中結果を書き込みます。

### 木ができる途中を読む補足

公開版の `Parser` は、トークン列と次に読む添字 `pos` を持つオブジェクトです。オブジェクトは関連する情報・操作をまとめたものです。`parser.expression()` の内部の `self` は、そのparser自身を指します。`self.current` は現在のトークンを見るだけで位置を進めず、`self.take()` はそのトークンを返してposを1増やします。別の規則を呼んでも、同じ位置を引き継ぎます。

`2+3*4` のトークンの添字は `2:0、+:1、3:2、*:3、4:4、eof:5` です。ここでのposは文字列の位置ではなくトークン列の添字です。規則がどこまで読んで何を返すかを、次の順で見ます。

| 読む規則と動き | pos | できている木 |
| --- | --- | --- |
| expression → term → factorが2を読む | 0 → 1 | Number(2.0)。termは+を読まず返す |
| expressionが+を読む | 1 → 2 | 左の2の木を保持し、右のtermを呼ぶ |
| 右のterm → factorが3を読む | 2 → 3 | 右側の左の木はNumber(3.0) |
| termが*、factorが4を読む | 3 → 5 | Binary("*", Number(3.0), Number(4.0)) |
| expressionが左右をつなぐ | 5のまま | 足し算を根に持つ木。parseがeofを確認 |

`Number` は数値の葉、`Binary` は演算子・左の子・右の子を持つ木の部品です。ここでtermが返すのは3×4の木で、数値12ではありません。`evaluate` が木を受け取った後に3×4を12、2+12を14と評価します。詳細は `lectures/08.md` の「途中1」〜「途中3」、公開解説は `instructor/08.md` にあります。この途中例はBの理解を助けるもので、新しい提出課題ではありません。

## C　実装または拡張

submission/08に電卓を作り、字句・構文・評価を別関数に分けます。参照版はスライドのEBNF全体に対応します。学生演習の基本必須は整数表記と `3.5` のように小数点の前後に数字がある表記です。`3.`、`.5` は発展として実装してもかまいません。対応範囲をREADMEに明示し、基本例は全て満たします。

`starter.py` は基礎の電卓を呼ぶ動作例です。拡張課題は、独立の検査・表示・テストを増やすことです。自力実装する場合も完成例と比較してかまいません。

| 経路 | 開始状態と本人の作業 |
| --- | --- |
| 完成基礎電卓を利用して拡張 | 動く字句・構文・評価を利用し、submission/08に本人の検査・表示・テストなどを作る。利用元と変更範囲をREADMEで示す |
| 自作で全実装 | submission/08に字句・構文・評価を別関数で作り、各段階の結果を完成例と比較して検証する |

いずれもA・Bの説明と以下の受入例を用います。完成参照を利用した範囲と、本人が実装して確認した範囲を区別してreflectionに書きます。

受入例（正常な入力）：

|入力|期待値または失敗|
|---|---|
|`2+3*4`|14|
|`(2+3)*4`|20|
|`-3*2`|-6|
|`8/2/2`|2|
|`0.1+0.2`|誤差を考慮して0.3に近い|

受入例（拒否する入力）：

|入力|期待する失敗|
|---|---|
|`2@3`|字句エラー|
|`(2+3`|構文エラー|
|`2 3`|余分なトークンとして構文エラー|
|`1/0`|評価エラー|

```bash
python3 examples/08-calculator/calculator.py --eval '2+3*4'
python3 -m unittest discover -s submission/08 -v
```

エラーメッセージを出しただけで合格にせず、該当段階をテストします。例を手計算してから実行します。

## 確認

`2+*3`は読めるトークンですが、並びが不正です。ASTは空白そのものより意味を持つ構造を残します。`10-3-2`は左結合です。ゼロ除算は構文として合法な式の評価条件です。自分の処理系で各理由を説明します。
