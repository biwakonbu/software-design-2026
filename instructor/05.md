# 第05回 教員用：グラフの設計

学生配布用は `lectures/05.md` と `exercises/05.md`。解答や説明例を含む教員用資料。正式な時間・採点配分は設定しない。

## 到達目標と進行

頂点・辺・向き・重みを要求から決め、BFSの発見時記録と親の復元へつなぐ。グラフ理論の網羅より、次回の経路課題の仕様を説明できることを重視する。実例の駅名や路線図は転載せず、架空校内マップでモデルの範囲を話す。

説明、図と隣接リストの照合、手作業のキュー追跡、入力変更、確認問題の順で進める。正式な所要分数を固定しない。

## 実演の正解

`examples/05-graphs/graphs.py` のグラフはA-B、A-C、B-D、C-D、孤立X。AからDのBFS経路はA B D。Aから到達する集合はA B C D、連結成分は `{A,B,C,D}` と `{X}` の2つ。

Aの隣接順をB、CとしたBFSの追跡例：開始キューA、Aの取り出し後B C、Bの取り出し後C D、Cの取り出し後D。Dの親はBのまま。探索をgoal発見時に止める実装では、最後までの訪問順を求める実演と出力が異なるので、停止条件を確認する。

## 次数の説明

今回の単純無向グラフでは次数は隣接頂点数、Aは2、Xは0。無向の自己ループを扱う拡張では次数の数え方が変わるので、今回の前提を示す。有向グラフは入次数・出次数と呼ぶ。値の符号を意味しない。相互に有向辺が存在することと、モデル全体を無向と定義することも区別する。

## 確認問題の解説

1. 一方通行を無向として登録すると、許可されない逆向き移動を返す。元の意味を変える誤モデル。
2. 頂点をキューに追加した時点で発見済みにする。取り出した時点まで遅らせると、複数の親から同じ頂点を重複追加し得る。
3. 重みなし、または全辺の移動費用が同じ正の定数の場合、最少辺数と最少総費用が一致する。時間や料金が辺ごとに異なれば、BFSだけでは最少総費用を保証しない。
4. 関数は既知の孤立頂点への到達不能を `None` で返せる。未知の頂点名は別に検証し、入力エラーとして扱う。

## 演習の解説

無向辺B-Dを両方向から削れば、A Dの最短経路はA C D。さらにC-Dを両方向から削れば到達不能。片側だけ削ると「無向」の前提を壊す。有向A B、B DではAからDは到達可能、DからAは到達不能。出次数は隣接リスト長、入次数は全ての隣接リストに対象が現れる回数で求める。

同じ長さの最短経路が複数ある場合、1本返す仕様なら、経路文字列の完全一致だけを正解条件にしない。開始・終了、各辺の存在、最少辺数を確認する。教材の固定データは順序を固定してA B Dを期待する。

## よくある誤解と支援

訪問済みは循環対策だけでなく、重複した発見を避ける。parentを後から上書きすると、最初の距離の根拠を失う。DFSで経路が見つかることと、その経路が最短であることを区別する。全経路の列挙はこの回のBFS1本返却とは別の仕様であり、候補数が非常に増え得る。

無向グラフの循環検出は直前の親への辺を除外する。単純なvisited判定だけで親への戻りを循環と誤判定しない。有向グラフで到達可能な集合を1つ求めても、強連結の証明にはならない。

理解に詰まった学生には、コードをいったん閉じ、図の辺を両方向の隣接リストへ転記させる。次にキューの先頭を1個ずつ消し、追加した親だけを書く。

## 口頭確認と到達の目安

「この辺の意味は何ですか」「Dの親がCへ変わらない理由は何ですか」「時間の最短へ仕様を変えると、何のデータが必要ですか」と確認する。

到達の目安は、モデルの前提を言えること、対称な隣接リストを作れること、発見時記録と復元を説明できること。正式な評価は別途案内する。
