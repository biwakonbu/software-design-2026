## 対象環境の解説

完成参照の環境は `(frame-cell parent)`、セルは `(bindings)`、束縛は `(name value)`。`m-new-env` は空のセルと外側を持つ環境を返す。`m-bindings` は現在の束縛を取り出す。`m-find` は現在にない名前を外側で探し、`m-lookup` は値を返す。

外側Gの `x = 5`、子Eの `y = 3` を例に、Eの `y` は3、Eから探した `x` はGの5となる。ホストの環境を検索する処理ではない。`define` は右辺を対象の `m-eval` で評価してから `m-define` で現在の環境へ登録する。

クロージャは環境への参照を保存する。`m-define` が共有セルの束縛を更新するので、その環境を捕捉した関数は後から登録した自分の定義も見つけられる。参照方言のcdrはコピーを返す。取り出したcdrを書き換えたつもりでは元の束縛は変わらないため、環境操作を関数で隠す理由をここで確認する。

## squareの解答と途中状態

1. 対象のlambdaをGで評価し、`(closure (x) ((* x x)) G)` 相当の値を作る。Gは実際の対象環境への参照であり、文字列Gではない。
2. `(square 6)` の先頭からクロージャ、引数から値の列 `(6)` を得る。
3. `m-apply` が個数を確認し、保存環境Gを外側に持つE6を作る。E6へ `x = 6` を束縛する。
4. 本文 `(* x x)` の `*` はG、各 `x` はE6で見つける。引数値6と6を組込みへ渡し、36を返す。

Gの束縛を引数で上書きしない。呼出し元を外側に付け替えない。学生には結果36だけでなく、本文の検索先を示させる。

## クロージャと再帰の解答

対象の `make-adder 5` から作った `add5 3` は8。対象のx=5の環境が返された関数から参照され、次のy=3の環境の外側となる。第10回の4状態図を対象環境へ読み替える。

対象の `fact 4` は24。第10回の `fact 2` の下降と復帰を先に追い、各nの独立と同じfact定義の共有を確認する。自作で未完の場合も完成参照で理解確認を行い、本人の実装との差を特定する。

## REPL統合の解答

`m-repl(env)` は同じ対象環境を各入力へ渡す。`read-all` で得た式の列を `m-sequence` が順に評価し、`m-eval` と `m-apply` が対象の意味を決める。環境は循環をまたいで保持し、入力と結果は1回の処理に属する。

`guard` の保護範囲には読取、評価、display、newlineを含める。成功なら先頭が#t、失敗なら#fと診断を含む結果を返す。失敗時は診断し、次の入力へ進む。表示でホストの数値制限に達する場合も回復する。

`(define x 5)`、`(+ x 2)`、`(/ 1 0)`、`(+ x 3)` の順に、x、7、診断、8を得る。エラー以前の束縛や出力は取り消さない。EOFと単独の:quitは終了。空行・コメントも参照版の扱いを確認する。

`--meta --eval` は対象評価器のみ、`--selfhost-repl` はLisp製循環を起動する。読取はPythonのtokenize/read_all、算術・リストprimitive、入出力、guard、反復whileもホストに依存する。独立bootstrapやネイティブ実行は達成範囲に含めない。

## チェックポイントの扱い

補足 `examples/14-selfhosting/checkpoints.py` は既存実装で最小式、環境、クロージャ、REPLを観察するdriver。提出条件やfixtureを増やすものではない。引数minimal/environment/closure/replで地点を選ぶ。closureのE6は同じm-new-env/m-bind/m-sequenceで分解して作る観察用環境であり、通常m-apply内部の環境を捕捉したログではない。通常呼出しの36と比較する。本人には通った地点、入力と結果、使った参照、変更箇所を従来の実行記録に対応付けさせる。

評価器でsquareが失敗する場合はREPLを足さず、名前、クロージャ生成、引数値、子環境、本文の順に縮める。評価器が動いてから、定義継続、回復、終了を同じセッションで確かめる。

## よくある誤解

「同じ結果が出たのでLisp製評価器が動いた」では入口の証拠がない。「対象環境は毎回初期化してよい」では定義が次の入力で使えない。「Pythonが起動に関わるだけ」では読取・入出力などの依存を過小に述べる。独立ブートストラップ・ネイティブ実行は達成したと表現しない。
