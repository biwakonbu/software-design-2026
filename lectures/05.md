# グラフ理論とは

グラフ理論は、対象と対象のつながりを **頂点** と **辺** で抽象化し、到達・経路・連結などの構造の性質を調べる数学の分野です。

| 呼び名 | 表すもの |
| --- | --- |
| 折れ線グラフ・棒グラフ | 数値の変化や大小を、軸の上に描いた図 |
| この回のグラフ | ものとものの間のつながりそのもの |

同じ「グラフ」という言葉でも別物です。この回は、つながりの構造だけを扱います。

# 頂点・辺・隣接の言葉

頂点は対象を、辺は2つの頂点のつながりを表します。

| 用語 | 意味 | 校内マップの例 |
| --- | --- | --- |
| 頂点 vertex | 対象1つ | 場所A、B、C、D、X |
| 辺 edge | 2頂点のつながり1つ | 通路A–B |
| 隣接 | 1本の辺で直接つながる | AとB（AとDは隣接しない） |
| 孤立頂点 | 辺が1本もない頂点 | X |

頂点を節点・ノード（node）と呼ぶ資料もあります。公開コードの変数名は `vertex` です。

# BFSが最小費用にもなる条件

BFSが保証するのは辺数の最少です。費用の最小とは、条件付きで一致します。

| 各辺の費用 | BFSの経路は最小費用か |
| --- | --- |
| すべて1（移動1回） | はい。費用＝辺数 |
| すべて同じ正の値c | はい。費用＝c×辺数 |
| 2分と10分が混在 | 保証しない（前の図の例） |
| 0や負の値を含む | 保証しない |

重み付きの最小費用には別の方法が必要です。この回では実装しません。

`graph` は dict（対応表）で、キーが頂点名、値が隣接先の list です。

# 次数

単純無向グラフでは、頂点につながる辺の数を次数と呼びます。

有向グラフでは、出ていく辺を **出次数**、入ってくる辺を **入次数** として数えます。

```python
directed = {"A": ["B"], "B": ["D"], "D": []}

```

次数の値に正負の符号がある、という意味ではありません。

# 循環になる列、ならない列

循環を判定するときは、同じ辺の往復と区別します。

| 頂点の列 | 循環か | 理由 |
| --- | --- | --- |
| A, B, D, C, A | 循環 | 別々の辺AB・BD・DC・CAで戻る |
| A, B, A | 循環ではない | 同じ辺ABを往復しただけ |
| A, B, D, B, A | 循環ではない | 辺AB・BDを往復しただけ |

往復は循環に数えません。そのため、循環のない木の上でも A, B, A の往復は起こります。

# 幅優先と深さ優先

名前は、候補をどちらへ先に広げるかを表します。

| 探索 | 候補の入れ物 | 取り出す順 |
| --- | --- | --- |
| BFS 幅優先（breadth-first） | queue（キュー） | FIFO（先入れ先出し）：先に入れた候補から |
| DFS 深さ優先（depth-first） | stack（スタック） | LIFO（後入れ先出し）：最後に入れた候補から |

BFSは近い層を広げ切ってから次の層へ進みます。DFSは1本の枝を奥まで進んでから戻ります。

# deque の基本操作

`collections.deque` は、両端から出し入れできる列です。次は確認用の短い例です。

```python
from collections import deque
queue = deque(["A"])
queue.append("B")
queue.append("C")
print(queue.popleft())  # A
print(queue.pop())      # C
```

`append` は右端へ追加します。`popleft` は左端（最も古い候補）、`pop` は右端（最も新しい候補）を取り出します。BFSは `popleft` を使います。

# FIFOだと距離の順になる理由

AからDのBFSで、キュー（左が先頭）と各頂点の距離を並べます。

| 時点 | キュー | 距離 |
| --- | --- | --- |
| 開始 | A | 0 |
| Aを処理した後 | B, C | 1, 1 |
| Bを処理した後 | C, D | 1, 2 |
| Cを処理した後 | D | 2 |

距離1の頂点が先に出るので、最初にDを発見した辺B–Dで距離2が確定します。

# Bを処理するときの値

queue が B, C の状態で、B を取り出した場面です。

| 変数・式 | 値 |
| --- | --- |
| `vertex` | `'B'` |
| `graph[vertex]` | `['A', 'D']` |
| `neighbor` が `'A'` | previous にあるので何もしない |
| `neighbor` が `'D'` | `previous['D'] = 'B'`、queue へ追加 |

取り出した直後の queue は C だけ、処理後は C, D です。

# 訪問済みを記録する理由

BとCの両方からDへ行ける場合を考えます。

1. Bを処理してDを発見し、キューへ入れる
2. Cを処理したとき、Dはすでに発見済み
3. Dを再びキューへ入れず、最初の親を保つ

各頂点を1回だけキューへ入れれば、循環があっても探索を終了できます。

# 公開コードの経路復元

```python
        if vertex == goal:
            path = []
            cursor: str | None = goal
            while cursor is not None:
                path.append(cursor)
                cursor = previous[cursor]
            return path[::-1]
```

`cursor` は復元中に今いる頂点です。`previous[cursor]` で1つ前へ移り、Aの前の None で止まります。

`path[::-1]` は逆順の新しいリストを作り、それを返します。

# 復元の状態変化

goal の D から、D → B → A → None の順にたどります。

| 回 | append した cursor | path |
| --- | --- | --- |
| 1回目 | `'D'` | `['D']` |
| 2回目 | `'B'` | `['D', 'B']` |
| 3回目 | `'A'` | `['D', 'B', 'A']` |
| 終了 | cursor が None | 逆順で `['A', 'B', 'D']` |

# 同じ頂点の場合と到達不能の場合

goal が start と同じ A なら、最初の `popleft` で `vertex == goal` です。`previous['A']` は None なので、結果は `['A']` です。

到達しない goal について `previous[goal]` を読まないので、KeyError も起きません。

# bfs が返すのは処理順

```python
    while queue:
        vertex = queue.popleft()
        result.append(vertex)

```

# BFSの計算量

隣接リストで、各頂点と各隣接要素を一通り調べます。

- 時間：O(V + E)
- 追加領域：探索本体のキューと親記録にO(V)
- 公開版の入力検査：`adjacency_sets` にO(V + E)
- 入力グラフ自体：O(V + E)

辞書・集合の操作を平均的にO(1)とみなすモデルです。

探索ごとに経路全体をコピーする実装では、追加コストを別に数えます。

# DFSを選ぶ場面

DFSは、奥の分岐を調べて戻る操作に合います。

- 到達する頂点の列挙
- 循環の検出や依存関係の検討
- 分岐を選び直す探索

DFSで最初に見つけた経路の辺数が最少とは限りません。

求めたい答えの条件から、探索法を選びます。

# dfs のループ

```python
    while stack:
        vertex = stack.pop()
        if vertex in visited:
            continue
        visited.add(vertex)
        result.append(vertex)
        stack.extend(reversed(graph[vertex]))
```

開始時は `stack = [start]`、`visited = set()`、`result = []` です。`set()` は空の集合で、`{}` と書くと空の辞書になります。

`pop()` は最後に積んだ候補を取り出します。処理済みなら `continue` で次の候補へ進みます。

<LearningStyles05 />

# reversed で積む理由

`graph["A"]` は `['B', 'C']` です。隣接順どおり B から深く進みたいのに、stack は最後に積んだものから出ます。

| 書き方 | 積んだ後 | 次の pop |
| --- | --- | --- |
| `stack.extend(graph["A"])` | `['B', 'C']` | C |
| `stack.extend(reversed(graph["A"]))` | `['C', 'B']` | B |

`reversed` は元のリストを変えずに、逆の順で要素を渡します。

# dfs の状態を追う（前半）

| --- | --- | --- |
| 開始 | `[]` | `['A']` |
| A | `['A']` | `['C', 'B']` |
| B | `['A', 'B']` | `['C', 'D', 'A']` |
| A（処理済み） | 変化なし | `['C', 'D']` |

| --- | --- | --- |

# 成分を1つずつ取り出す

# validate_graph の検査

```python
    for vertex, neighbors in graph.items():
        for neighbor in neighbors:
            if neighbor not in graph:
```

`graph.items()` は、頂点とその隣接リストの組を順に渡します。

# 無向の逆辺検査

`g1 = {"A": ["B"], "B": []}` で比べます。`*,` より後ろの `undirected` は、名前を付けて渡す引数です。

| 呼出し | 結果 |
| --- | --- |
| `validate_graph(g1)` | 通過（有向グラフとして正しい） |
| `validate_graph(g1, undirected=True)` | ValueError：BからAへの辺がない |
| `validate_graph({"A": ["Z"]})` | ValueError：Zが未定義 |

`adjacency_sets` は各隣接リストを set にした写しで、逆辺の有無を平均O(1)で調べます。

# 公開APIの追加領域

時間はどの公開関数も O(V + E) です。追加領域は、部品ごとに分けて数えます。

| 部品 | 追加領域 |
| --- | --- |
| `shortest_path` の queue と previous | O(V) |
| `_bfs` の visited と result | O(V) |
| `validate_graph` の adjacency_sets | O(V + E)。undirected=False でも作る |
| `dfs` の stack | 候補が重複するので O(V) とは限らない |

どの公開関数も最初に検査するので、全体の追加領域は O(V + E) です。
