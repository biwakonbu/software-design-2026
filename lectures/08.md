```mermaid
flowchart LR

  E --> F[意味を検査して評価]
```

字句は文字の単位、構文は並び方、意味は演算の成立条件を扱う。

# 字句解析の入力と出力

入力は `12 + 3.5`。

| 種類 | 文字列 | 開始位置（0始まり） |
|---|---|---:|
| number | `12` | 0 |
| + | `+` | 3 |
| number | `3.5` | 5 |
| eof | 空文字列 | 8 |

位置を保持すると、エラーの発生箇所を伝えられる。

---

# 数字をまとめる

`123` は3つの数ではなく、1つの数値トークン。

```text
現在位置0: 1を読む
現在位置1: 2も数字なので続ける
現在位置2: 3も数字なので続ける
終端に到達: "123"をnumberとして確定
```

空白なしの `12+3` も、演算子を境界にして分ける。

---

# 空白と不正な文字

```text
2 + 3      number, +, number, eof
2+3        number, +, number, eof
2 @ 3      @ の位置で字句エラー
```

空白は読み飛ばす。知らない文字を勝手に取り除かない。<br>
`2 @ 3` を23や5として解釈すると、入力の意味を変えてしまう。

---

# EBNFによる数値の表記

```text
digit  = "0" | "1" | ... | "9" ;
digits = digit, { digit } ;
number = digits, [ ".", { digit } ]
       | ".", digits ;
```

`{ }` は0回以上、`[ ]` は省略可能を表す。<br>
この教材は `3`、`3.5`、`3.`、`.5` を許し、`.` だけは拒否する。

---

# 構文はトークンの並び方

| 入力 | 字句 | 構文 |
|---|---|---|
| `2 + 3` | 全て識別できる | 有効 |
| `2 + * 3` | 全て識別できる | オペランド不足 |
| `(2 + 3` | 全て識別できる | 閉じ括弧不足 |
| `2 3` | 全て識別できる | 余分な数値 |

字句が読めても、式として成立するとは限らない。

---

# 抽象構文木（AST）

```mermaid
flowchart TD
  A[＋] --> B[2]
  A --> C[×]
  C --> D[3]
  C --> E[4]
```

`2 + 3 * 4` は、3と4の積を右の子に持つ。<br>
空白や括弧そのものは、木のノードとして残す必要がない。

---

# 優先順位を文法にする

```text
expression = term, { ("+" | "-"), term } ;
term       = factor, { ("*" | "/"), factor } ;
factor     = number
           | ("+" | "-"), factor
           | "(", expression, ")" ;
```

expressionがtermを、termがfactorを読む。<br>
内側で読んだまとまりが、木の子になる。

---

# 再帰下降パーサー

文法の規則ごとに関数を用意する。

```python
def expression(self):
    node = self.term()
    while self.current.kind in ("+", "-"):
        op = self.take().kind
        node = Binary(op, node, self.term())
    return node
```

左の式を先に木にすることで、減算の左結合を表す。

---

# 左結合と計算結果

```text
10 - 3 - 2
正しい木: (10 - 3) - 2 = 5
別の木:   10 - (3 - 2) = 9
```

演算子の優先順位だけでなく、同じ優先順位の結合方向も仕様になる。

**検証**：`8 / 2 / 2` は、この教材では2になる。

---

# 括弧の扱い

```text
factorが "(" を見つける
  expressionで内側の式を読む
  ")" が続くことを確認する
  内側の木を返す
```

閉じ括弧がなければ構文エラー。<br>
括弧の中の式も同じ文法なので、再帰で入れ子を扱える。

---

# 単項マイナス

```text
-3 * 2
Binary("*", Unary("-", Number(3)), Number(2))
結果: -6
```

単項マイナスは引数1つ。減算は引数2つ。<br>
同じ文字でも、式の中での位置が役割を決める。

---

# ASTを評価する

```python
if isinstance(node, Number):
    return node.value
if isinstance(node, Binary):
    left = evaluate(node.left)
    right = evaluate(node.right)
    if node.op == "+":
        return left + right
```

子の値を求めてから、親の演算を適用する。<br>
第4回の木の走査が、式の評価につながる。

---

# 意味の検査と実行時の失敗

`1 / 0` は字句も構文も正しいが、数値の除算として成立しない。

```python
if node.op == "/":
    if right == 0:
        raise CalculatorError("division by zero")
    return left / right
```

この電卓では、評価時に意味上の条件を検査する。<br>
一般の言語では、型や名前を実行前に検査する処理系もある。

---

# 3段階のエラーを比較する

| 例 | 段階 | 理由 |
|---|---|---|
| `2 @ 3` | 字句 | 未知の文字 |
| `2 + * 3` | 構文 | 値が必要な位置に `*` |
| `1 / 0` | 意味・評価 | ゼロでの除算 |

同じ「動かない」でも、修正すべき場所が異なる。

# 数値表現の限界

内部のfloatには、10進小数を厳密に表せない値がある。

```text
0.1 + 0.2 は、内部で厳密な0.3とは限らない。
```

整数の例は結果を一致で確認する。小数のテストは誤差を考慮する。<br>
金額の厳密な計算などでは、数値表現そのものを設計する必要がある。
